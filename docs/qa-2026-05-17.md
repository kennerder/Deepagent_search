> 主题：路由、记忆、搜索、评测

## 路由模块

### Q1: BERT 多标签 sigmoid 算出来的分数加起来 ≠1，为什么？

**A:** sigmoid 不求和为 1 是 feature 不是 bug。

| | Softmax | Sigmoid |
|---|---|---|
| 公式 | `e^xᵢ / Σe^x` | `1/(1+e^(-xᵢ))` |
| 求和 | = 1.0 | 无约束 |
| 含义 | 多选一，份额互相挤压 | 多选多，彼此独立 |

类比：Softmax 是三个人分 100 块钱，sigmoid 是三个人各自独立面试，可能都通过也可能都不通过。

对于"查布洛芬库存并搜索最新市场行情"，sigmoid 输出 `[db: 0.87, web: 0.79, kb: 0.12]` 求和 1.78，两个子代理同时激活，这才是正确的。

### Q2: 能同时激活三个子代理吗？

**A:** 能。每个标签完全独立判断，三个都过阈值就三个全激活。没有任何数量限制，0 到 3 个都有可能。

### Q3: 命中多个子代理时，子 Agent 收到的是原 query 还是拆解后的？

**A:** 当前是原 query 原封不动传给子 Agent，靠主 Agent LLM 自己写 `task(description=...)` 时拆解。已补充了 LLM Query 拆解功能——命中多个子代理时，LLM 自动将原 query 拆为各子代理的精准子任务，通过 route_hint 注入。

### Q4: LLM 拆解 Query 时出现幻觉怎么办？

**A:** 三层防御：

| 层 | 机制 | 拦截什么 |
|---|---|---|
| L1 | Prompt 严格约束"只拆不增，禁止编造" | LLM 自由发挥 |
| L2 | jieba TF-IDF 实体覆盖率校验（≥50%）+ 编造率校验（<50%） | 意图丢失/编造加戏 |
| L3 | 校验失败回退传原 query | 零风险兜底 |

### Q5: 实体错配（串台）能被校验抓出来吗？

**A:** 不能。这是已知局限。

当 LLM 把 A 意图的实体错配给 B 子代理（如"布洛芬库存"分配给 web_search，"阿莫西林政策"分配给 db_query），合并后的实体集合仍然完整——覆盖率检查通过，但分配交叉了。这是 NLU 开放域语义理解问题，当前没有可靠的自动校验手段。依赖主 Agent LLM 看到原始 query 后自行纠正 `task()` 调用。

### Q6: BERT 三个标签是推理了三次吗？

**A:** 不是。一次 forward pass 输出 shape `(1, 3)` 的 logits，三个标签分数同时计算。已优化掉代码里重复的 predict 调用，只跑一次 `predict(return_all_scores=True)`。

### Q7: "什么都不属于"怎么处理？

**A:** 三段式路由决策：

```
全部 < 0.35  →  "none"     → 显式告知主 Agent "不需要子代理，直接回答"
0.35~0.5     →  "fallback" → 不给建议，LLM 自己判断
≥ 0.5        →  "bert"     → 注入路由建议 + 子任务
```

## 对话记忆

### Q8: 项目做记忆系统了吗？怎么做的？

**A:** 已实现。三层设计：

| 层 | 机制 | 作用 |
|---|---|---|
| 短期记忆 | `ConversationMemory`，按 thread_id 隔离，保留最近 20 轮 | 多轮对话上下文 |
| 上下文注入 | 新一轮查询时，最近 5 轮历史格式化为自然语言注入 prompt | 让 Agent 知道在说什么 |
| 指代消解 | 路由模块加载对话历史，LLM 消解省略句 | "那销售额呢？"→"布洛芬销售额" |

### Q9: 多用户同时访问怎么实现隔离的？

**A:** 靠 Python `ContextVar`。它是 asyncio 原生机制，每个 Task 独立拷贝，不需要锁。

```
Task 1: _thread_id_ctx.set("abc")  ← 只对 Task 1 可见
Task 2: _thread_id_ctx.set("xyz")  ← 只对 Task 2 可见
```

三层隔离：ContextVar 隔离会话目录和 WebSocket 推送，thread_id 做 key 隔离对话记忆。

### Q10: 每个用户的 ID 怎么获取的？

**A:** UUID4 自动生成会话 ID。当前没有用户系统（无登录、无鉴权），是会话级别的隔离。上线前需要补 userId 体系。

### Q11: 单 worker 和多 worker 什么区别？

**A:** `uvicorn --workers N` 控制启动多少个 OS 进程。

- **单 worker**：所有请求一个进程，记忆共享零成本，但 BERT CPU 推理排队
- **多 worker**：请求随机分配，BERT 分摊，但 dict 型记忆跨进程不通，需 Redis 后端

当前先 `--workers 1` 够用。

## 网络搜索

### Q12: 并行搜索受 Python GIL 影响吗？

**A:** 不受。GIL 只锁 CPU 计算，不锁 I/O 等待。HTTP 请求在 `socket.recv()` 等待响应时自动释放 GIL，5 个线程真正同时等网络。总耗时 ≈ 单次搜索耗时，不是 5 倍。

### Q13: 网络搜索还有哪些优化方向？

**A:** 按投入产出比：

| 优先级 | 优化项 | 说明 |
|---|---|---|
| 高 | 结果综合摘要 | LLM 将原始结果提炼为结构化报告，省主 Agent 一轮上下文 |
| 中 | 语义去重 | URL 不同但内容几乎相同，embedding 相似度 >0.85 的丢掉 |
| 中 | 自适应搜索深度 | 简单事实 2 条，一般查询 3 条，开放研究 5 条 |

## RAG 与评测

### Q14: RAG 动态 TopK 的"动态"指什么？

**A:** 不固定返回前 N 条，而是检测 Cross-Encoder 分数的"断崖"自动截断。

```
分数序列: [0.95, 0.93, 0.89, 0.77, 0.71]
                            ↑ 断崖：0.89→0.77 跌了13%
```

两种断崖条件：相对差 >25% 或绝对差 >0.5，满足其一即截断。最少保留 3 条，最多 10 条。

### Q15: RAG 能做评测吗？用什么指标？

**A:** 能做。分层评测：

| 层级 | 工具 | 指标 |
|---|---|---|
| 检索层（离线） | 人工标注 + 代码 | Recall@K, MRR, NDCG |
| 端到端（在线） | RAGAS（LLM 当裁判） | Faithfulness, Answer Relevancy, Context Precision, Context Recall |

**Recall 的正确用法**：测下限不卷上限。Recall@20 < 0.3 说明检索有 bug；≥ 0.8 就够了，应该转去盯 Faithfulness。

### Q16: Recall@K 的 K 怎么取？

**A:** 多个 K 都报：

- Recall@5：测 Reranker 精排质量（实际喂给 LLM 的条数）
- Recall@10：测排序中段质量
- Recall@20：测 Qdrant 粗排覆盖力

K 越大指标越高但跟实际效果越脱节。RAG 里 Recall@5 最实际。
